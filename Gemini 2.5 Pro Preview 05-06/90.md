### 081: [162. 寻找峰值 (Find Peak Element)](https://leetcode.cn/problems/find-peak-element)

**题目描述:**
峰值元素是指其值严格大于左右相邻值的元素。
给你一个整数数组 `nums`，找到峰值元素并返回其索引。数组可能包含多个峰值，在这种情况下，返回 **任何一个峰值** 所在位置即可。
你可以假设 `nums[-1] = nums[n] = -∞` 。
你必须实现时间复杂度为 O(log n) 的算法来解决此问题。

**解题思路 (变种二分查找):**
由于题目要求 O(log n) 的时间复杂度，自然想到二分查找。关键在于如何根据 `nums[mid]` 与其邻居的关系来缩小搜索范围。
题目假设 `nums[-1] = nums[n] = -∞`，这意味着数组的两端外侧是负无穷。

1.  初始化 `left = 0`, `right = nums.length - 1`。
2.  当 `left < right` 时循环 (注意是 `<` 而不是 `<=`)：
    a.  计算 `mid = left + (right - left) // 2`。
    b.  比较 `nums[mid]` 和 `nums[mid + 1]`：
    i.  **如果 `nums[mid] < nums[mid + 1]`**: 说明 `mid` 处于一个上升的坡度上，峰值一定在 `mid` 的右侧 (包括 `mid+1` 本身也可能是峰值，或者 `mid+1` 后面有更大的值形成峰值)。所以，我们可以舍弃左半部分，包括 `mid`：`left = mid + 1`。
    ii. **如果 `nums[mid] > nums[mid + 1]`**: 说明 `mid` 处于一个下降的坡度上，或者 `mid` 本身就是一个峰值。峰值一定在 `mid` 的左侧或者 `mid` 本身。所以，我们可以舍弃右半部分，但保留 `mid` 作为潜在的峰值：`right = mid`。
3.  当循环结束时 (`left == right`)，`left` (或 `right`) 指向的元素就是其中一个峰值。返回 `left`。

**为什么这样可行?**
*   如果 `nums[mid] < nums[mid+1]`: 我们知道 `mid` 右边有个更高的点 `mid+1`。由于数组最右端是负无穷，那么从 `mid+1` 开始往右，必然会经历一个先上升后下降（或一直下降）的过程，所以峰值肯定在 `[mid+1, n-1]` 区域。
*   如果 `nums[mid] > nums[mid+1]`: 我们知道 `mid` 左边（最左端是负无穷）和 `mid` 与 `mid+1` 之间构成了一个潜在的峰。峰值肯定在 `[0, mid]` 区域。

**Python 实现:**
```python
class Solution:
    def findPeakElement(self, nums: list[int]) -> int:
        left, right = 0, len(nums) - 1
        
        while left < right:
            mid = left + (right - left) // 2
            if nums[mid] < nums[mid + 1]:
                # Peak is in the right half (mid+1 might be a peak, or further right)
                left = mid + 1
            else: # nums[mid] >= nums[mid + 1] (could be a peak or on a downward slope from a peak)
                  # Peak is in the left half including mid
                right = mid
                
        # When left == right, we have found a peak
        return left
```

**Java 实现:**```java

### 082: [695. 岛屿的最大面积 (Max Area of Island)](https://leetcode.cn/problems/max-area-of-island)

**题目描述:**
给你一个大小为 `m x n` 的二进制矩阵 `grid` 。
**岛屿** 是由一些相邻的 `1` (代表土地) 构成的组合，这里的「相邻」要求两个 `1` 必须在 **水平或者竖直方向上** 相邻。你可以假设 `grid` 的四个边缘都被 `0` (代表水) 包围着。
岛屿的面积是岛上值为 `1` 的单元格的数目。
计算并返回 `grid` 中最大的岛屿面积。如果没有岛屿，则返回 `0` 。

**解题思路:**
与“岛屿数量”问题类似，遍历整个网格。当遇到一个 `'1'`（陆地）并且这个陆地没有被访问过时，就找到了一个新的岛屿。然后，从这个点开始，使用深度优先搜索 (DFS) 或广度优先搜索 (BFS) 来计算当前岛屿的面积，并将所有属于该岛屿的陆地标记为已访问（例如，可以将 `'1'` 变成 `'0'`）。同时，维护一个全局的最大面积变量。

1.  初始化 `max_area = 0`。
2.  获取网格的行数 `rows` 和列数 `cols`。
3.  遍历网格中的每个单元格 `grid[r][c]`：
    a.  如果 `grid[r][c] == 1`:
        i.  调用 DFS 或 BFS 函数，从 `(r, c)` 开始，计算当前岛屿的面积 `current_area`。在DFS/BFS过程中，将访问过的 `'1'` 标记为 `'0'`。
        ii. `max_area = max(max_area, current_area)`。
4.  返回 `max_area`。

**DFS 辅助函数 `dfs(grid, r, c)` 返回当前连通岛屿的面积:**
1.  边界检查和条件检查：如果 `(r, c)` 超出边界，或者 `grid[r][c]` 不是 `1`，则返回 `0` (没有面积贡献)。
2.  标记当前单元格为已访问：`grid[r][c] = 0`。
3.  当前单元格贡献面积 `1`。
4.  递归地访问四个相邻方向，并将它们的面积贡献累加到当前岛屿面积中：
    *   `area = 1 + dfs(grid, r + 1, c) + dfs(grid, r - 1, c) + dfs(grid, r, c + 1) + dfs(grid, r, c - 1)`。
5.  返回 `area`。

**Python 实现 (DFS):**
```python
class Solution:
    def maxAreaOfIsland(self, grid: list[list[int]]) -> int:
        if not grid or not grid[0]:
            return 0

        rows = len(grid)
        cols = len(grid[0])
        max_area = 0

        def dfs(r, c) -> int:
            # Boundary checks or if it's water or already visited (marked as 0)
            if r < 0 or r >= rows or c < 0 or c >= cols or grid[r][c] == 0:
                return 0
            
            grid[r][c] = 0 # Mark as visited (sink the island part)
            current_cell_area = 1
            
            # Explore neighbors and sum their areas
            current_cell_area += dfs(r + 1, c) # Down
            current_cell_area += dfs(r - 1, c) # Up
            current_cell_area += dfs(r, c + 1) # Right
            current_cell_area += dfs(r, c - 1) # Left
            return current_cell_area

        for r in range(rows):
            for c in range(cols):
                if grid[r][c] == 1:
                    current_island_area = dfs(r, c)
                    max_area = max(max_area, current_island_area)
        
        return max_area
```

**Java 实现 (DFS):**
```java
class Solution {
    private int rows;
    private int cols;

    public int maxAreaOfIsland(int[][] grid) {
        if (grid == null || grid.length == 0 || grid[0].length == 0) {
            return 0;
        }

        rows = grid.length;
        cols = grid[0].length;
        int maxArea = 0;

        for (int r = 0; r < rows; r++) {
            for (int c = 0; c < cols; c++) {
                if (grid[r][c] == 1) {
                    int currentIslandArea = dfs(grid, r, c);
                    maxArea = Math.max(maxArea, currentIslandArea);
                }
            }
        }
        return maxArea;
    }

    private int dfs(int[][] grid, int r, int c) {
        // Boundary checks or if it's water or already visited (marked as 0)
        if (r < 0 || r >= rows || c < 0 || c >= cols || grid[r][c] == 0) {
            return 0;
        }

        grid[r][c] = 0; // Mark as visited
        int currentCellArea = 1;

        currentCellArea += dfs(grid, r + 1, c); // Down
        currentCellArea += dfs(grid, r - 1, c); // Up
        currentCellArea += dfs(grid, r, c + 1); // Right
        currentCellArea += dfs(grid, r, c - 1); // Left
        
        return currentCellArea;
    }
}
```

**复杂度分析:**
*   时间复杂度: O(M * N)，其中 M 是行数，N 是列数。每个单元格最多被访问两次。
*   空间复杂度: O(M * N) 在最坏情况下 (递归栈深度，如果整个网格是一个大岛屿)。如果使用非递归BFS，则为队列大小。

### 083: [113. 路径总和 II (Path Sum II)](https://leetcode.cn/problems/path-sum-ii)

**题目描述:**
给你二叉树的根节点 `root` 和一个整数目标和 `targetSum` ，找出所有 **从根节点到叶子节点** 路径总和等于给定目标和的路径。
**叶子节点** 是指没有子节点的节点。

**解题思路 (回溯/DFS):**
使用深度优先搜索 (DFS) 来遍历树的路径。在DFS过程中，维护当前路径上的节点和当前路径的总和。
1.  定义一个结果列表 `all_paths` 来存储所有符合条件的路径。
2.  定义一个DFS辅助函数 `dfs(node, current_sum, current_path)`:
    *   `node`: 当前访问的节点。
    *   `current_sum`: 从根节点到 `node` 的父节点为止的路径和。
    *   `current_path`: 从根节点到 `node` 的父节点为止的路径上的节点值列表。
3.  **DFS函数逻辑**:
    a.  如果 `node` 为空，直接返回。
    b.  将当前节点 `node.val` 加入 `current_path`，更新路径和 `path_sum_so_far = current_sum + node.val`。
    c.  **检查叶子节点和目标和**:
    *   如果 `node` 是叶子节点 (即 `node.left` 为空且 `node.right` 为空) 并且 `path_sum_so_far == targetSum`:
    *   将 `current_path` 的一个副本加入 `all_paths`。
    d.  **递归探索子节点**:
    *   递归调用 `dfs(node.left, path_sum_so_far, current_path)`。
    *   递归调用 `dfs(node.right, path_sum_so_far, current_path)`。
    e.  **回溯**: 在从当前节点的递归调用返回之前，将 `node.val` 从 `current_path` 中移除 (恢复到进入此节点前的状态)。
4.  初始调用 `dfs(root, 0, [])` (Python) or `dfs(root, targetSum, new ArrayList<>(), resultList)` (Java - 传递剩余目标和)。
    **Alternative strategy**: DFS function could be `dfs(node, remaining_sum, current_path)`.
    * `remaining_sum = targetSum - node.val`.
    * If `node` is leaf and `remaining_sum == 0`.

Let's use `dfs(node, current_path_sum, current_path_nodes)` approach.

**Python 实现:**
```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

class Solution:
    def pathSum(self, root: TreeNode, targetSum: int) -> list[list[int]]:
        all_paths = []
        
        def dfs(node, current_path_nodes, path_sum):
            if not node:
                return

            # Add current node to the path and update sum
            current_path_nodes.append(node.val)
            path_sum += node.val
            
            # Check if it's a leaf node and path sum equals targetSum
            if not node.left and not node.right: # It's a leaf node
                if path_sum == targetSum:
                    all_paths.append(list(current_path_nodes)) # Add a copy of the path
            else:
                # Continue DFS on children
                dfs(node.left, current_path_nodes, path_sum)
                dfs(node.right, current_path_nodes, path_sum)
            
            # Backtrack: remove current node from path and sum (implicitly handled by path_sum being a local var if not careful)
            # More explicitly: path_sum is passed by value effectively in python recursive calls,
            # but current_path_nodes is a list (mutable) and needs popping.
            current_path_nodes.pop()
            # No need to subtract from path_sum if path_sum is passed as a new value in each recursive call like in many DFS.
            # However, if using class member for path_sum, or updating a single path_sum reference, then subtract here.
            # In this setup, path_sum being local to each stack frame, so no explicit subtraction needed on backtrack.

        dfs(root, [], 0)
        return all_paths
```

**Java 实现:**
```java
import java.util.ArrayList;
import java.util.List;

class TreeNode {
    int val;
    TreeNode left;
    TreeNode right;
    TreeNode() {}
    TreeNode(int val) { this.val = val; }
    TreeNode(int val, TreeNode left, TreeNode right) {
        this.val = val;
        this.left = left;
        this.right = right;
    }
}

class Solution {
    public List<List<Integer>> pathSum(TreeNode root, int targetSum) {
        List<List<Integer>> allPaths = new ArrayList<>();
        findPaths(root, targetSum, new ArrayList<>(), allPaths);
        return allPaths;
    }

    private void findPaths(TreeNode node, int remainingSum, List<Integer> currentPathNodes, List<List<Integer>> allPaths) {
        if (node == null) {
            return;
        }

        // Add current node to the path
        currentPathNodes.add(node.val);
        int newRemainingSum = remainingSum - node.val;

        // Check if it's a leaf node and path sum equals targetSum
        if (node.left == null && node.right == null) { // It's a leaf node
            if (newRemainingSum == 0) {
                allPaths.add(new ArrayList<>(currentPathNodes)); // Add a copy
            }
        } else {
            // Continue DFS on children
            findPaths(node.left, newRemainingSum, currentPathNodes, allPaths);
            findPaths(node.right, newRemainingSum, currentPathNodes, allPaths);
        }
        
        // Backtrack: remove current node from path
        currentPathNodes.remove(currentPathNodes.size() - 1);
    }
}
```

**复杂度分析:**
*   时间复杂度: O(N*H) in worst case (N nodes, H height for path copy), or O(N^2) for skewed tree. If just counting paths it's O(N). Path copying for each valid path is the main factor for "path reporting" problems. A tighter bound is O(N) if we consider visiting each node, and sum of lengths of all paths. For a tree with L leaves, if all paths to leaves are valid, this sum can be O(L*H). For a balanced tree, L=N/2, H=logN. For skewed tree, L=1, H=N.
    Let's say N nodes. The DFS itself visits each node once (O(N)). For each leaf, if it's a valid path, we copy the path of length up to H. Max leaves N/2. Total: O(N + NumValidPaths * H). A loose upper bound is O(N*H) because each node may be part of H path constructions.

*   空间复杂度: O(H) for recursion stack and `current_path` list. In worst case (skewed tree), H can be N, so O(N). `all_paths` storage is separate, can be O(N*H) or more.

### 084: [662. 二叉树最大宽度 (Maximum Width of Binary Tree)](https://leetcode.cn/problems/maximum-width-of-binary-tree)

**题目描述:**
给你一棵二叉树的根节点 `root` ，返回树的 **最大宽度** 。
树的 **最大宽度** 是所有层中最大的宽度。
每一层的宽度被定义为该层最左和最右的非空节点（两端点）之间的长度。不存在的节点也计入长度计算。也就是说，返回 层内最左边的非空节点和最右边的非空节点之间的 个数 (包含端点和中间的所有 null 节点).

**解题思路 (BFS + 节点编号):**
1.  使用 BFS (层序遍历) 来逐层处理节点。
2.  为每个节点分配一个索引/编号。如果根节点编号为 `idx`，则其左子节点编号为 `2 * idx`，右子节点编号为 `2 * idx + 1` (使用1-based indexing for root helps to avoid `2*0=0`, `2*0+1=1` which leads to non-unique child indexing if root is 0 and use `2*idx` and `2*idx+1`. So, let root be `1`. Left child `2*idx`, Right child `2*idx + 1`. Or, root is `0`, left `2*idx+1`, right `2*idx+2`).
    Let's use root=0, left child= `2*idx`, right child= `2*idx+1`. (this can cause problems when index becomes large, will address later). For a fixed level `d`, nodes could be indexed from `0` to `2^d -1`.
3.  在 BFS 的每一层：
    a.  记录该层最左边节点的编号 `min_idx_this_level` 和最右边节点的编号 `max_idx_this_level`。
    b.  该层的宽度是 `max_idx_this_level - min_idx_this_level + 1`。
    c.  更新全局最大宽度 `max_overall_width`。
4.  队列中存储 `(node, index)` 对。
5.  **处理索引过大问题**:
    直接使用 `2*idx` 会导致索引值随层数指数增长，可能溢出。
    一个技巧是，在每一层，将所有节点的索引相对于该层最左边节点的索引进行归一化。
    如果队列中存储 `(node, original_index)`:
    *   当开始处理一层时，队列中的第一个元素 `(first_node_in_level, first_original_index)` 的 `first_original_index` 可以作为该层的偏移量。
    *   对于队列中取出的 `(node, original_index)`，其在当前层的相对索引是 `original_index - first_original_index`。
    *   其子节点的新原始索引应该是 `(original_index - first_original_index) * 2` 和 `(original_index - first_original_index) * 2 + 1`。

    Alternatively, without subtracting the offset for children and only for width calculation:
    At each level, `first_node_index = queue.peek().index`.
    Then for each node `(curr, curr_idx)` dequeued:
    Left child goes to queue as `(curr.left, curr_idx * 2)`.
    Right child goes to queue as `(curr.right, curr_idx * 2 + 1)`.
    The width for the current level is `last_node_idx_in_level - first_node_idx_in_level + 1`.
    To avoid huge numbers if we use root=0: left=2i, right=2i+1. For root=1: left=2i, right=2i+1.
    This indexing ensures that the difference between rightmost and leftmost nodes' indices directly gives (count - 1).
    Using root_idx=0 scheme: root=0, left_child= `2*idx`, right_child=`2*idx+1`. This doesn't work because both left and right of node 0 are 0, which is wrong.
    Use: root = 0. Left child of `idx` is `2*idx + 1`. Right child of `idx` is `2*idx + 2`.
    This results in a "heap-like" indexing. `0` for root. Level 1: `1, 2`. Level 2: `3, 4, 5, 6`.
    The width would then be `rightmost_index - leftmost_index + 1`. This works well.

**Python 实现 (BFS + 0-based heap indexing):**
```python
from collections import deque

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

class Solution:
    def widthOfBinaryTree(self, root: TreeNode) -> int:
        if not root:
            return 0

        max_width = 0
        # Queue stores tuples of (node, index)
        # Using 0-based indexing for root, left child index = 2 * parent_index + 1, right = 2 * parent_index + 2
        queue = deque([(root, 0)]) 

        while queue:
            level_size = len(queue)
            # Get the index of the first node at this level (leftmost)
            # This will be used to normalize indices and prevent large numbers for width calculation for this level
            level_leftmost_index = queue[0][1] 
            
            current_level_left_idx = -1
            current_level_right_idx = -1

            for i in range(level_size):
                node, index = queue.popleft()
                
                # Normalized index for the current node within this level for width calculation
                normalized_index = index - level_leftmost_index

                if i == 0: # First node of the level
                    current_level_left_idx = index # Use original index here for storing min/max
                if i == level_size - 1: # Last node of the level
                    current_level_right_idx = index

                if node.left:
                    queue.append((node.left, 2 * index + 1))
                if node.right:
                    queue.append((node.right, 2 * index + 2))
            
            # Calculate width for this level: (index_of_rightmost - index_of_leftmost + 1)
            max_width = max(max_width, current_level_right_idx - current_level_left_idx + 1)
            
        return max_width

```
Wait, the indexing for Python using `2*idx+1` and `2*idx+2` can get very large. A better strategy for Python with arbitrary precision integers is to only store the index and use the `index - level_leftmost_index` for `normalized_index`, but keep the *original* full index when enqueuing children. The `max_width` is updated with `rightmost_node_index_in_level - leftmost_node_index_in_level + 1`.

Let's rethink Python index to match Java version:
Root node gets index 1. Left child `2*idx`. Right child `2*idx + 1`.

```python
from collections import deque

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

class Solution: # Corrected indexing for Python (1-based root for 2*i, 2*i+1 scheme)
    def widthOfBinaryTree(self, root: TreeNode) -> int:
        if not root:
            return 0

        max_width = 0
        # Queue stores (node, index). Root has index 1.
        queue = deque([(root, 1)])

        while queue:
            level_size = len(queue)
            leftmost_idx_this_level = queue[0][1] # Index of the first node in the current level
            rightmost_idx_this_level = queue[-1][1] # Index of the last node encountered so far on this level.
                                                 # Better to get this after the loop for the level

            # Store the first and last index encountered in THIS LEVEL's processing
            level_first_idx = -1
            level_last_idx = -1

            for i in range(level_size):
                node, index = queue.popleft()
                
                if i == 0:
                    level_first_idx = index
                if i == level_size - 1:
                    level_last_idx = index

                if node.left:
                    queue.append((node.left, 2 * index))
                if node.right:
                    queue.append((node.right, 2 * index + 1))
            
            max_width = max(max_width, level_last_idx - level_first_idx + 1)
            
        return max_width
```


**Java 实现 (BFS + 1-based heap indexing to prevent overflow or handle it with long):**
Indices can still get large. In Java, use `long` for indices if necessary, or apply relative indexing within a level *for child computation*. The simpler method is using `long` if indices fit. Max nodes ~3000 means max depth ~3000. 2^3000 is too big.
The question implies node position, not value.
The "null node counting" is tricky. Width = `(idx_rightmost - idx_leftmost + 1)`.
Correct BFS Level Processing:
1. `max_width = 0`
2. Queue stores `(node, position_idx)`
3. `queue.add((root, 1))`
4. `while queue not empty`:
   `level_size = queue.size()`
   `level_start_idx = queue.peek().position_idx`
   `current_node_pos = 0`
   `for i = 0 to level_size-1`:
   `curr_node, pos = queue.poll()`
   `current_node_pos = pos` // Will store the rightmost pos of this level by end of loop
   `if curr_node.left: queue.add((curr_node.left, 2 * (pos - level_start_idx) + X))` // If use relative
   Alternatively, directly compute full indices: `(curr_node.left, 2 * pos))` if root = 1
   `max_width = max(max_width, current_node_pos - level_start_idx + 1)`
5. Return `max_width`

This approach might still make `pos` very large.
A better approach is `queue.add( (node, relative_pos_on_level) )`, then when calculating width, `max_width = max(max_width, max_relative_pos_on_level - min_relative_pos_on_level + 1)`. This won't work because child position must be absolute to its parent.

Let's stick to the root=1, left=2\*idx, right=2\*idx+1 using `long` for indices in Java.

```java
import java.util.LinkedList;
import java.util.Queue;

class TreeNode {
    int val;
    TreeNode left;
    TreeNode right;
    TreeNode() {}
    TreeNode(int val) { this.val = val; }
    TreeNode(int val, TreeNode left, TreeNode right) {
        this.val = val;
        this.left = left;
        this.right = right;
    }
}

class Pair { // Helper class for Java queue
    TreeNode node;
    long index; // Use long to avoid overflow for deep/wide trees
    Pair(TreeNode node, long index) {
        this.node = node;
        this.index = index;
    }
}

class Solution {
    public int widthOfBinaryTree(TreeNode root) {
        if (root == null) {
            return 0;
        }

        long maxWidth = 0;
        Queue<Pair> queue = new LinkedList<>();
        // Root node has index 1. Left child 2*idx, Right child 2*idx + 1.
        queue.offer(new Pair(root, 1L));

        while (!queue.isEmpty()) {
            int levelSize = queue.size();
            long levelFirstIndex = -1L; // Index of the first node in this level
            long levelLastIndex = -1L;  // Index of the last node in this level

            for (int i = 0; i < levelSize; i++) {
                Pair current = queue.poll();
                TreeNode node = current.node;
                long index = current.index;

                if (i == 0) { // This is the leftmost node of the current level
                    levelFirstIndex = index;
                }
                // This node is encountered, so it could be the rightmost so far
                levelLastIndex = index;

                if (node.left != null) {
                    queue.offer(new Pair(node.left, 2 * index));
                }
                if (node.right != null) {
                    queue.offer(new Pair(node.right, 2 * index + 1));
                }
            }
            
            // Width of the current level
            // Check if levelFirstIndex was set (i.e., level was not empty)
            if (levelFirstIndex != -1L) {
                 maxWidth = Math.max(maxWidth, levelLastIndex - levelFirstIndex + 1);
            }
        }
        return (int)maxWidth;
    }
}
```

**复杂度分析:**
*   时间复杂度: O(N)，每个节点访问一次 (BFS)。
*   空间复杂度: O(W)，W 是树的最大宽度（BFS 队列大小）。

### 085: [62. 不同路径 (Unique Paths)](https://leetcode.cn/problems/unique-paths)

**题目描述:**
一个机器人位于一个 `m x n` 网格的左上角 （起始点在下图中标记为 “Start” ）。
机器人每次只能向下或者向右移动一步。机器人试图达到网格的右下角（在下图中标记为 “Finish” ）。
问总共有多少条不同的路径？

**解题思路 (动态规划):**
1.  定义 `dp[i][j]` 为从左上角 `(0,0)` 到达单元格 `(i,j)` 的不同路径数。
2.  **初始化**:
    *   第一行 `dp[j]` 只能从左边过来，所以 `dp[j] = 1` for all `j`.
    *   第一列 `dp[i]` 只能从上边过来，所以 `dp[i] = 1` for all `i`.
    *   `dp = 1` (虽然可以视为从上方或左方过来，但通常我们说起始点有一条路径到达自身，或者基于以上两条初始化).
3.  **状态转移方程**:
    *   要到达 `(i,j)`，机器人只能从 `(i-1,j)` (向下移动) 或 `(i,j-1)` (向右移动)过来。
    *   所以 `dp[i][j] = dp[i-1][j] + dp[i][j-1]` for `i > 0, j > 0`.
4.  最终结果是 `dp[m-1][n-1]`。

**空间优化:**
由于 `dp[i][j]` 只依赖于上一行 `dp[i-1][...]` 和当前行已计算的部分 `dp[i][j-1]`，可以将空间优化到 O(n) (使用一维数组存储上一行的状态) 或 O(min(m,n))。
If using one row: `dp_row[j] = dp_row[j] (value from above) + dp_row[j-1] (value from left)`.

**Python 实现 (O(m*n) space):**
```python
class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        # Create a dp table initialized with 0s or 1s.
        # dp[i][j] = number of ways to reach cell (i, j)
        dp = [[0 for _ in range(n)] for _ in range(m)]

        # Initialize first row and first column to 1
        # (since there's only one way to reach any cell in the first row/col: move right/down)
        for i in range(m):
            dp[i][0] = 1
        for j in range(n):
            dp[0][j] = 1
            
        # Fill the dp table
        for i in range(1, m):
            for j in range(1, n):
                dp[i][j] = dp[i-1][j] + dp[i][j-1]
                
        return dp[m-1][n-1]

# Python space optimized (O(n) space)
class SolutionSpaceOptimized:
    def uniquePaths(self, m: int, n: int) -> int:
        # Uses a single row for DP state
        dp_row = [1] * n # Represents the dp values for the current row being computed

        for i in range(1, m): # Iterate through rows starting from the second row
            for j in range(1, n): # Iterate through columns
                # dp_row[j] (from cell above) is its current value from previous row's calculation
                # dp_row[j-1] (from cell to the left) is the updated value in this row's pass
                dp_row[j] = dp_row[j] + dp_row[j-1] 
                
        return dp_row[n-1]

```

**Java 实现 (O(m*n) space):**

// Java space optimized (O(n) space)
class SolutionSpaceOptimized {
    public int uniquePaths(int m, int n) {
        int[] dpRow = new int[n];
        // Initialize the first "virtual" row (all 1s)
        for (int j = 0; j < n; j++) {
            dpRow[j] = 1; 
        }

        for (int i = 1; i < m; i++) { // Iterate through rows (m-1 times more)
            // dpRow[0] remains 1 (path from top)
            for (int j = 1; j < n; j++) { // Iterate through columns
                // dpRow[j] (value from cell above, i.e., from previous iteration's dpRow[j])
                // dpRow[j-1] (value from cell to the left, already updated in this iteration for current row)
                dpRow[j] = dpRow[j] + dpRow[j-1];
            }
        }
        return dpRow[n-1];
    }

```**Combinatorial Solution:**
This is also a combinatorics problem. To reach `(m-1, n-1)` from `(0,0)`, the robot needs to make a total of `(m-1) + (n-1)` moves. Out of these total moves, `m-1` must be downward moves (or `n-1` rightward moves). The number of ways is `C(total_moves, downward_moves) = C((m-1)+(n-1), m-1)`.
This can be computed as `( (m+n-2)! / ((m-1)! * (n-1)!) )`.

*   时间复杂度: O(M * N).
*   空间复杂度: O(M * N) or O(min(M,N)) with optimization. Combinatorial O(1) space (if calculating combination iteratively without large number issues or using math libs).

### 086: [152. 乘积最大子数组 (Maximum Product Subarray)](https://leetcode.cn/problems/maximum-product-subarray)

**题目描述:**
给你一个整数数组 `nums` ，请你找出数组中乘积最大的非空连续子数组（该子数组中至少包含一个数字），并返回该子数组所对应的乘积。

**解题思路 (动态规划):**
与“最大子数组和” (Kadane's Algorithm) 类似，但乘积问题因为负数的存在而变得复杂 (负负得正)。
我们需要同时追踪以当前元素结尾的**最大乘积**和**最小乘积** (因为一个大的负数乘以另一个负数可能得到一个非常大的正数)。

1.  初始化 `max_so_far = nums`, `min_so_far = nums`, `result = nums`。
    (These track the max/min product *ending at the current position*).
2.  从数组的第二个元素 `nums[i]` 开始遍历：
    a.  获取当前元素 `num = nums[i]`。
    b.  由于 `num` 可能是负数，它会使得之前的 `max_so_far` 乘以它后变成最小，`min_so_far` 乘以它后变成最大。所以，当 `num` 是负数时，交换 `max_so_far` 和 `min_so_far` 的角色 (在计算新值之前)。
    c.  更新以 `nums[i]` 结尾的最大乘积：
        `current_max_product = max(num, max_so_far_ending_at_prev * num)`
        `current_min_product = min(num, min_so_far_ending_at_prev * num)`
    d.  更新全局最大乘积 `result = max(result, current_max_product)`。
    Store the calculated `current_max_product` and `current_min_product` for the next iteration (as `max_so_far` and `min_so_far`).

Let's refine state definition:
`max_prod_ending_here = nums[i]`
`min_prod_ending_here = nums[i]`

For `i` from 1 to n-1:
Let `num = nums[i]`.
Candidates for new `max_prod_ending_here`:
  1. `num` (start a new subarray with `num`)
  2. `prev_max_prod_ending_here * num`
  3. `prev_min_prod_ending_here * num` (if `num` is negative, this could be large positive)
Similarly for `min_prod_ending_here`.

Simplified:
`dp_max[i]` = max product of subarray ending at `i`.
`dp_min[i]` = min product of subarray ending at `i`.

If `nums[i]` is positive:
  `dp_max[i] = max(nums[i], dp_max[i-1] * nums[i])`
  `dp_min[i] = min(nums[i], dp_min[i-1] * nums[i])`
If `nums[i]` is negative:
  `dp_max[i] = max(nums[i], dp_min[i-1] * nums[i])` (min becomes max)
  `dp_min[i] = min(nums[i], dp_max[i-1] * nums[i])` (max becomes min)

Keep a global `max_overall_product`.

**Python 实现:**
```python
class Solution:
    def maxProduct(self, nums: list[int]) -> int:
        if not nums:
            return 0

        # Initialize max_prod_ending_here, min_prod_ending_here, and overall_max_product with the first element
        # These track the max/min product for subarrays ending at the current position
        max_ending_here = nums[0]
        min_ending_here = nums[0]
        overall_max_product = nums[0]

        for i in range(1, len(nums)):
            num = nums[i]
            
            # If num is negative, max_ending_here will become min and min_ending_here will become max
            # So, we might need to swap them before calculating new values.
            # Store the previous max_ending_here to calculate the new min_ending_here correctly.
            temp_max_ending_here = max_ending_here 
            
            # Calculate new max product ending at current position
            # It can be num itself, num * previous_max_ending_here, or num * previous_min_ending_here
            max_ending_here = max(num, num * max_ending_here, num * min_ending_here)
            
            # Calculate new min product ending at current position
            # It can be num itself, num * previous_max_ending_here (using stored temp), or num * previous_min_ending_here
            min_ending_here = min(num, num * temp_max_ending_here, num * min_ending_here)
            
            # Update overall max product
            overall_max_product = max(overall_max_product, max_ending_here)
            
        return overall_max_product
```

**Java 实现:**
```java

        if (nums == null || nums.length == 0) {
            return 0;
        }

        // Initialize maxProdEndingHere, minProdEndingHere, and overallMaxProduct with the first element
        int maxEndingHere = nums[0];
        int minEndingHere = nums[0];
        int overallMaxProduct = nums[0];

        for (int i = 1; i < nums.length; i++) {
            int num = nums[i];

            maxEndingHere = Math.max(num, Math.max(num * maxEndingHere, num * minEndingHere));

            // It's num itself, or num multiplied by previous (temp) max or min
            minEndingHere = Math.min(num, Math.min(num * tempMaxEndingHere, num * minEndingHere));
            
            // Update overall max product
            overallMaxProduct = Math.max(overallMaxProduct, maxEndingHere);
        }
        
        return overallMaxProduct;
    }
}

### 087: [112. 路径总和 (Path Sum)](https://leetcode.cn/problems/path-sum)

**题目描述:**
给你二叉树的根节点 `root` 和一个表示目标和的整数 `targetSum` 。判断该树中是否存在 **根节点到叶子节点** 的路径，这条路径上所有节点值相加等于目标和 `targetSum` 。如果存在，返回 `true` ；否则，返回 `false` 。
**叶子节点** 是指没有子节点的节点。

**解题思路 (DFS/递归):**
1.  **基准情况**:
    *   如果 `root` 为空，路径不存在，返回 `false`。
    *   如果 `root` 是叶子节点 ( `root.left == null` and `root.right == null`):
        *   检查 `root.val == targetSum` (if passing `targetSum - root.val` down, check `targetSum == 0` at leaf).
        *   如果相等，返回 `true`。否则，返回 `false`。
2.  **递归步骤**:
    *   计算新的目标和: `newTargetSum = targetSum - root.val`。
    *   递归地在左子树中查找路径: `hasPath(root.left, newTargetSum)`。
    *   递归地在右子树中查找路径: `hasPath(root.right, newTargetSum)`。
    *   如果左子树或右子树中任何一个找到了路径，则返回 `true`。
    *   否则，返回 `false`。

**Python 实现:**
```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

class Solution:
    def hasPathSum(self, root: TreeNode, targetSum: int) -> bool:
        if not root:
            return False # An empty tree cannot have any path

        # Check if it's a leaf node
        if not root.left and not root.right:
            return root.val == targetSum # Path sum is just the leaf's value
        
        # Recursively check left and right subtrees with the updated target sum
        remaining_sum = targetSum - root.val
        
        found_in_left = False
        if root.left:
            found_in_left = self.hasPathSum(root.left, remaining_sum)
        
        found_in_right = False
        if root.right:
            found_in_right = self.hasPathSum(root.right, remaining_sum)
            
        return found_in_left or found_in_right
```

### 088: [198. 打家劫舍 (House Robber)](https://leetcode.cn/problems/house-robber)

**题目描述:**
你是一个专业的小偷，计划偷窃沿街的房屋。每间房内都藏有一定的现金，影响你偷窃的唯一制约因素就是相邻的房屋装有相互连通的防盗系统，**如果两间相邻的房屋在同一晚上被小偷闯入，系统会自动报警**。
给定一个代表每个房屋存放金额的非负整数数组，计算你 **不触动警报装置的情况下** ，一夜之内能够偷窃到的最高金额。

**解题思路 (动态规划):**
`dp[i]` 表示偷到第 `i` 间房子为止（包括可能偷第 `i` 间）所能获得的最大金额。
对于第 `i` 间房子，小偷有两种选择：
1.  **偷第 `i` 间房子**: 那么就不能偷第 `i-1` 间。此时的最大金额是 `dp[i-2] + nums[i]` (偷了第 i-2 间及之前的最大金额，再加上第 i 间的)。
2.  **不偷第 `i` 间房子**: 那么最大金额与偷到第 `i-1` 间房子为止的最大金额相同，即 `dp[i-1]`。
    So, `dp[i] = max(dp[i-2] + nums[i], dp[i-1])`.

**基准情况**:
*   `dp = nums` (只有一间房，必须偷)
*   `dp = max(nums, nums)` (两间房，选金额大的那一间偷)

**空间优化**:
`dp[i]` 只依赖 `dp[i-1]` 和 `dp[i-2]`，所以可以用两个变量来迭代计算。
Let `rob_prev1` be the max money if we rob up to house `i-1`.
Let `rob_prev2` be the max money if we rob up to house `i-2`.
For house `i`: `current_max_rob = max(rob_prev2 + nums[i], rob_prev1)`.
Then update `rob_prev2 = rob_prev1`, `rob_prev1 = current_max_rob`.

**Python 实现 (空间优化):**
```python

    def rob(self, nums: list[int]) -> int:
        n = len(nums)
        if n == 0:
            return 0
        if n == 1:
            return nums[0]

        # For space optimization:
        rob_prev2 = 0       # Max money robbing up to i-2 houses (dp[i-2])
        rob_prev1 = 0       # Max money robbing up to i-1 houses (dp[i-1])
                            # Initialize based on 0 houses being 0

        for current_money_in_house in nums:
            # current_max is max money if we consider up to current_house
            # Option 1: rob current_house -> current_money_in_house + rob_prev2 (cannot rob previous)
            # Option 2: don't rob current_house -> rob_prev1 (max money from robbing previous houses)
            temp_current_max = max(current_money_in_house + rob_prev2, rob_prev1)
            
            rob_prev2 = rob_prev1
            rob_prev1 = temp_current_max
            
        return rob_prev1 # rob_prev1 will hold the max money after iterating through all houses
```

`temp = prev1`
`prev1 = max(prev2 + num, prev1)`

Return `prev1`.

Let's trace `nums =`:
Initial: `prev2=0`, `prev1=0`

5. `num = 1`: `temp=11`, `prev1=max(11+1, 11)=12`, `prev2=11`
   Result: `prev1=12`. This matches.

### 089: [179. 最大数 (Largest Number)](https://leetcode.cn/problems/largest-number)

**题目描述:**
给定一组非负整数 `nums`，重新排列每个数的顺序（每个数不可拆分）使之组成一个最大的整数。
**注意：** 输出结果可能非常大，所以你需要返回一个字符串而不是整数。

**解题思路 (自定义排序):**
关键在于如何比较两个数字 `a` 和 `b`，来决定它们在最终结果中的相对顺序。
如果我们将数字 `a` 放在 `b` 前面 (`ab`) 优于 将 `b` 放在 `a` 前面 (`ba`)，那么组合字符串 `str(a) + str(b)` 应该大于 `str(b) + str(a)`。
例如，比较 `3` 和 `30`:
`"3" + "30" = "330"`
`"30" + "3" = "303"`
Since `"330" > "303"`, `3` 应该在 `30` 前面。

1.  将所有数字转换为字符串。
2.  定义一个自定义比较函数 `compare(s1, s2)`: 如果 `s1 + s2 > s2 + s1`，则 `s1` 应该排在 `s2` 前面 (对于降序排序)。
3.  使用这个比较函数对字符串数组进行排序 (降序)。
4.  将排序后的字符串连接起来形成结果。
5.  **特殊处理**: 如果排序后的最大数是 "0" (例如输入是 ``)，则结果应该是 "0"，而不是 "000"。

**Python 实现:**
```python
import functools

class Solution:
    def largestNumber(self, nums: list[int]) -> str:
        # Convert numbers to strings
        str_nums = [str(num) for num in nums]

        # Custom comparison function
        def compare_nums(s1, s2):
            # For descending sort:
            # If s1+s2 is "larger", s1 should come before s2.
            # Python's functools.cmp_to_key expects:
            #   - negative if s1 < s2
            #   - zero if s1 == s2
            #   - positive if s1 > s2
            # For sorting in descending order for "s1+s2 > s2+s1":
            if s1 + s2 > s2 + s1:
                return -1 # s1 should come first (for descending logic, it means s1 is "smaller" in ascending sort context if sorting for larger combined value first)
            elif s1 + s2 < s2 + s1:
                return 1  # s2 should come first
            else:
                return 0

        # Sort the strings using the custom comparator
        str_nums.sort(key=functools.cmp_to_key(compare_nums))
        
        # Join the sorted strings
        result = "".join(str_nums)
        
        # Handle the edge case where the result is "0", "00", "000", etc.
        # (e.g., input [0, 0]). Result should be "0".
        if result[0] == '0': # This also handles the case of a single '0'
            return "0"
            
        return result
```

**Java 实现:**
```java
import java.util.Arrays;
import java.util.Comparator;

class Solution {
    public String largestNumber(int[] nums) {
        // Convert numbers to strings
        String[] strNums = new String[nums.length];
        for (int i = 0; i < nums.length; i++) {
            strNums[i] = String.valueOf(nums[i]);
        }

        // Custom comparator
        // We want to sort in an order such that s1+s2 > s2+s1 means s1 comes "before" s2.
        // Arrays.sort sorts in ascending order by default.
        // If we want s1 before s2 when (s2+s1) compared to (s1+s2) is smaller,
        // then comparator should return negative.
        // (s2+s1).compareTo(s1+s2) is what we need.
        Arrays.sort(strNums, new Comparator<String>() {
            @Override
            public int compare(String s1, String s2) {
                String order1 = s1 + s2;
                String order2 = s2 + s1;
                // For descending order based on this concatenation:
                return order2.compareTo(order1); // order2 larger -> s2 first
            }
        });

        // Join the sorted strings
        StringBuilder sb = new StringBuilder();
        for (String s : strNums) {
            sb.append(s);
        }
        
        String result = sb.toString();

        // Handle the edge case where the result is "0", "00", "000", etc.
        if (result.startsWith("0")) { //This means all numbers were 0.
            return "0"; 
        }
        
        return result;
    }
}
```

**复杂度分析:**
*   时间复杂度: O(N log N * L)，其中 N 是数字的数量，L 是数字的平均长度（字符串比较和连接的开销）。排序是 O(N log N) 次比较，每次比较涉及字符串连接和比较，长度可达 2L。
*   空间复杂度: O(N * L) or O(N) (for string array). Python's `str_nums` list, Java's `strNums` array.

### 090: [560. 和为K的子数组 (Subarray Sum Equals K)](https://leetcode.cn/problems/subarray-sum-equals-k)

**题目描述:**
给你一个整数数组 `nums` 和一个整数 `k` ，请你统计并返回 该数组中和为 `k` 的连续子数组的个数 。
子数组是数组中元素的连续非空序列。

**解题思路 (前缀和 + 哈希表):**
1.  **前缀和 (Prefix Sum)**:
    *   `prefix_sum[i]` 表示从 `nums` 到 `nums[i-1]` 的和。
    *   子数组 `nums[j...i]` (inclusive j, i) 的和是 `prefix_sum[i+1] - prefix_sum[j]`。
        (If prefix_sum array means sum up to `nums[i]`, then subarray `nums[j...i]` sum is `prefix_sum[i] - prefix_sum[j-1]`. If `j=0`, then it's `prefix_sum[i]`).
        Let's use current sum: `current_sum` = sum from `nums` to `nums[i]`.
        We are looking for a `j <= i` such that `sum(nums[j...i]) == k`.
        This means `current_sum_up_to_i - sum_up_to_j_minus_1 == k`.
        So, `sum_up_to_j_minus_1 = current_sum_up_to_i - k`.
2.  **算法**:
    *   初始化 `count = 0` (符合条件的子数组个数)。
    *   初始化 `current_sum = 0`。
    *   初始化一个哈希表 `prefix_sum_counts`，用于存储【某个前缀和】出现的【次数】。
        *   特别地，`prefix_sum_counts = 1`。这表示和为0的前缀 (空前缀) 出现过一次。这对于处理从数组开头开始的子数组和恰好为k的情况 (即 `current_sum - k == 0`) 很重要。
    *   遍历数组 `nums` 中的每个数字 `num`:
        a.  `current_sum += num`。
        b.  **查找**: 计算 `needed_prefix_sum = current_sum - k`。
        c.  如果 `needed_prefix_sum` 在 `prefix_sum_counts` 中，说明之前存在一个或多个前缀，它们与当前从头开始的子数组的差为 `k`。将 `prefix_sum_counts[needed_prefix_sum]` 累加到 `count`。
        d.  **更新哈希表**: 将 `current_sum` 加入 `prefix_sum_counts`，并增加其计数：`prefix_sum_counts[current_sum] = prefix_sum_counts.get(current_sum, 0) + 1`。
    *   返回 `count`。

**Python 实现:**
```python
from collections import defaultdict

class Solution:
    def subarraySum(self, nums: list[int], k: int) -> int:
        count = 0
        current_sum = 0
        # Stores prefix_sum -> frequency of that prefix_sum
        prefix_sum_counts = defaultdict(int)
        
        # For subarrays starting from index 0 whose sum is k
        # (current_sum - k == 0, so needed_prefix_sum is 0)
        prefix_sum_counts[0] = 1 
        
        for num in nums:
            current_sum += num
            
            # We are looking for a previous prefix sum `P` such that:
            # current_sum - P = k  =>  P = current_sum - k
            needed_prefix_sum = current_sum - k
            
            if needed_prefix_sum in prefix_sum_counts:
                count += prefix_sum_counts[needed_prefix_sum]
            
            # Add current_sum to the map
            prefix_sum_counts[current_sum] += 1
            
        return count
```

**Java 实现:**
```java
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int subarraySum(int[] nums, int k) {
        int count = 0;
        int currentSum = 0;
        // Stores prefixSum -> frequency of that prefixSum
        Map<Integer, Integer> prefixSumCounts = new HashMap<>();
        
        // For subarrays starting from index 0 whose sum is k
        // (currentSum - k == 0, so needed_prefix_sum is 0)
        prefixSumCounts.put(0, 1); 
        
        for (int num : nums) {
            currentSum += num;
            
            // We are looking for a previous prefix sum `P` such that:
            // currentSum - P = k  =>  P = currentSum - k
            int neededPrefixSum = currentSum - k;
            
            if (prefixSumCounts.containsKey(neededPrefixSum)) {
                count += prefixSumCounts.get(neededPrefixSum);
            }
            
            // Add currentSum to the map or update its frequency
            prefixSumCounts.put(currentSum, prefixSumCounts.getOrDefault(currentSum, 0) + 1);
        }
        
        return count;
    }
}
```

**复杂度分析:**
*   时间复杂度: O(N)，单次遍历数组，哈希表操作平均 O(1)。
*   空间复杂度: O(N)，哈希表在最坏情况下可能存储 N 个不同的前缀和。
